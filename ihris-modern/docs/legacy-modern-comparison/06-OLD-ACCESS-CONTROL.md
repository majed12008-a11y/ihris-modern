# المستخدمون والأدوار والصلاحيات (IHRIS Legacy Access Control)

## 1. نظرة عامة

يستخدم النظام القديم نموذج **RBAC (Role-Based Access Control)** مبسط لإدارة المستخدمين والأدوار والصلاحيات. يتم تخزين بيانات المستخدمين في جدول `user`، وصلاحيات الوصول في جدول `access`، وسجلات النشاط في جدول `user_log`، وإعدادات الصلاحية في جدول `config`.

---

## 2. جداول التحكم في الوصول

### 2.1 جدول `user` — المستخدمين

| العمود | النوع | قابلية NULL | الوصف |
|--------|-------|-------------|-------|
| id | int(11) | NO | معرف المستخدم (مفتاح أساسي) |
| username | varchar(20) | NO | اسم المستخدم (مUnique) |
| password | varchar(50) | NO | كلمة المرور (MD5 hash) |
| firstname | varchar(50) | NO | الاسم الأول |
| lastname | varchar(100) | NO | اسم العائلة |
| email | varchar(100) | YES | البريد الإلكتروني |
| creator | int(11) | NO | معرف المنشئ |

**الفهارس:** PRIMARY KEY (id), UNIQUE KEY username (username)

**عدد السجلات:** 55 (مبدئي، AUTO_INCREMENT=55)

**بيانات الدخول الافتراضية (من السجلات):**
| id | username | password (MD5) | firstname | lastname | email | creator |
|----|----------|----------------|-----------|----------|-------|---------|
| 1 | administrator | 330c0db82cab2fd53568cd5743fa973d | Site | Administrator | moh_it@moh.gov.ye | 0 |
| 54 | Majed | 330c0db82cab2fd53568cd5743fa973d | ماجد | الحداد | moh1@moh.org.ye | 1 |

**ملاحظة:** كلمة المرور `330c0db82cab2fd53568cd5743fa973d` هي hash لـ كلمة مرور شائعة (من المحتمل أن تكون "password" أو "admin" أو "123456").

---

### 2.2 جدول `access` — ربط المستخدمين بالأدوار

| العمود | النوع | قابلية NULL | الوصف |
|--------|-------|-------------|-------|
| user | int(11) | NO | معرف المستخدم (مفتاح أساسي، علاقة One-to-One مع user) |
| role | varchar(255) | NO | اسم الدور |

**الفهارس:** PRIMARY KEY (user)

**عدد السجلات:** 3+ 

**الأدوار المسجلة:**
| user | role |
|------|------|
| 1 | admin |
| 53 | admin |
| 54 | adm |

**ملاحظات:**
- كل مستخدم يمكن أن يكون له دور واحد فقط (بناءً على PRIMARY KEY على user)
- الأدوار مكتوبة كنصوص حرة (varchar 255)، وليس كمعرفات رقمية تشير إلى جدول أدوار منفصل
- الدور "adm" هو اختصار محتمل لـ "administrator" أو دور مختلف

---

### 2.3 جدول `user_log` — سجل النشاط

| العمود | النوع | قابلية NULL | الوصف |
|--------|-------|-------------|-------|
| user | int(11) | NO | معرف المستخدم (مفتاح خارجي إلى user.id) |
| login | datetime | NO | تاريخ تسجيل الدخول |
| logout | datetime | YES | تاريخ تسجيل الخروج |
| session_id | varchar(50) | NO | معرف الجلسة |
| activity | datetime | NO | تاريخ النشاط |

**الفهارس:** KEY user (user), KEY login (login)

**مثال على السجلات:**
| user | login | logout | session_id | activity |
|------|-------|--------|------------|----------|
| 53 | 2026-10-25 23:00:59 | 2026-10-26 00:18:22 | 1rjql1qkoegjait7i63um65rm2 | 2026-10-26 00:18:22 |
| 53 | 2026-10-26 18:40:38 | 2026-10-26 18:55:04 | 1rjql1qkoegjait7i63um65rm2 | 2026-10-26 18:55:04 |
| 1 | 2026-11-02 20:14:26 | NULL | 15jneo56aaabb59buuqc3ki9v6 | 2026-11-02 20:14:39 |

**ملاحظات:**
- يمكن أن يكون logout NULL إذا كان المستخدم ما زال مسجلاً دخولاً
- session_id يتتبع جلسات المستخدمين
- activity يسجل وقت النشاط الأخير

## 3. نموذج التحكم في الوصول (RBAC Model)

### 3.1 هيكل النموذج

```
المستخدم (user) ───── ruolo (role)
  1                    1
```

كل مستخدم يرتبط بدور واحد فقط. الأدوار معرفة كنصوص حرة في جدول `access`.

### 3.2 الأدوار المعرفة

| الدور | الوصف المتوقع | عدد المستخدمين |
|-------|--------------|---------------|
| admin | مسؤول النظام، الوصول الكامل | 2 (users 1, 53) |
| adm | دور مسؤول مختصر أو دور مختلف | 1 (user 54) |

**ملاحظة:** لا يوجد جدول منفصل للأدوار (roles table). الأدوار معرفة كنصوص في جدول `access` فقط، مما يعني أنه لا يمكن إدارة الأدوار بشكل مركزي أو إضافة وصف للأدوار.

---

## 3.3 إعدادات الصلاحية في جدول `config`

يحتوي جدول `config` على إعدادات للصلاحيات والوحدات النمطية. المسارات التالية تتعلق بالصلاحيات:

| المسار (path) | القيمة (value) | النوع (type) | الوصف |
|---------------|---------------|--------------|-------|
| config:I2CE/tasks/task_trickle_down/can_edit_database_lists/0 | can_view_database_lists | 1 | تسلسل الصلاحيات: يمكن عرض قواعد البيانات |
| config:I2CE/tasks/task_trickle_down/can_edit_database_lists/1 | can_view_all_database_lists | 1 | تسلسل الصلاحيات: يمكن عرض جميع قواعد البيانات |
| config:I2CE/tasks/task_trickle_down/custom_reports_can_access | NULL | 1 | يمكن الوصول للتقارير المخصصة |
| config:I2CE/tasks/task_trickle_down/custom_reports_can_access_reports | NULL | 1 | يمكن الوصول لتقارير مخصصة |
| config:I2CE/tasks/task_trickle_down/custom_reports_can_edit_reportViews | NULL | 1 | يمكن تعديل عروض التقارير |
| config:I2CE/tasks/task_trickle_down/custom_reports_can_view_reportViews | NULL | 1 | يمكن عرض عروض التقارير |
| config:I2CE/tasks/task_trickle_down/tasks_and_roles_admin | NULL | 1 | إدارة المهام والأدوار |
| config:I2CE/tasks/task_trickle_down/tasks_and_roles_can_access | NULL | 1 | يمكن الوصول للمهام والأدوار |
| config:I2CE/tasks/task_trickle_down/tasks_and_roles_can_edit_tasks | NULL | 1 | يمكن تعديل المهام |
| config:I2CE/tasks/task_trickle_down/tasks_and_roles_can_edit_roles | NULL | 1 | يمكن تعديل الأدوار |

**ملاحظات:**
- نظام الصلاحية يعتمد على "تسلسل الصلاحية" (trickle down) حيث تنتقل الصلاحيات من الأدوار العليا إلى الدنيا
- هناك صلاحيات عامة للتقارير المخصصة (custom_reports_can_access, custom_reports_can_access_reports, إلخ)
- هناك صلاحيات لإدارة المهام والأدوار (tasks_and_roles_*)

## 4. نموذج الصلاحية المفصل

### 4.1 الصلاحيات الأساسية (Core Permissions)

| الصلاحية | الوصف | الجدول المصدر |
|-----------|--------|---------------|
| can_edit_database_lists | يمكن تعديل قوائم قاعدة البيانات | config:I2CE/tasks/task_trickle_down/ |
| can_view_database_lists | يمكن عرض قوائم قاعدة البيانات | config:I2CE/tasks/task_trickle_down/ |
| can_view_all_database_lists | يمكن عرض جميع قواعد البيانات | config:I2CE/tasks/task_trickle_down/ |
| custom_reports_can_access | يمكن الوصول للتقارير المخصصة | config:I2CE/tasks/task_trickle_down/ |
| custom_reports_can_access_reports | يمكن الوصول لتقارير مخصصة | config:I2CE/tasks/task_trickle_down/ |
| custom_reports_can_edit_reportViews | يمكن تعديل عروض التقارير | config:I2CE/tasks/task_trickle_down/ |
| custom_reports_can_view_reportViews | يمكن عرض عروض التقارير | config:I2CE/tasks/task_trickle_down/ |
| tasks_and_roles_admin | إدارة المهام والأدوار | config:I2CE/tasks/task_trickle_down/ |
| tasks_and_roles_can_access | يمكن الوصول للمهام والأدوار | config:I2CE/tasks/task_trickle_down/ |
| tasks_and_roles_can_edit_tasks | يمكن تعديل المهام | config:I2CE/tasks/task_trickle_down/ |
| tasks_and_roles_can_edit_roles | يمكن تعديل الأدوار | config:I2CE/tasks/task_trickle_down/ |

### 4.2 تخصيص الصلاحية حسب الدور

لا يوجد جدول يربط الأدوار بالصلاحيات مباشرة. بدلاً من ذلك، تعتمد الصلاحيات على:
1. اسم الدور في جدول `access` (مثل "admin", "adm")
2. إعدادات التسلسل في جدول `config` (task_trickle_down)
3. مسارات الصلاحية في جدول `config`

هذا يعني أن نظام الصلاحية غير مرن ولا يدعم تخصيص الصلاحيات لكل دور بشكل منفصل.

## 5. قواعد العمل الخاصة بالصلاحية

| القاعدة | معرف | الوصف | مصدر الدليل |
|--------|-------|-------|-------------|
| BR-AC-001 | USER_ONE_ROLE | كل مستخدم يمكن أن يكون له دور واحد فقط | PRIMARY KEY (user) في جدول access |
| BR-AC-002 | USER_MUST_HAVE_ROLE | يجب أن يكون لكل مستخدم دور واحد على الأقل | وجود جدول access لربط المستخدمين بالأدوار |
| BR-AC-003 | ROLE_IS_TEXT_STRING | الدور مخزن كنص حر، ليس كمعرف رقمي | دور access.role هو varchar(255) |
| BR-AC-004 | NO_SEPARATE_ROLES_TABLE | لا يوجد جدول منفصل للأدوار | عدم وجود جدول roles في قاعدة البيانات |
| BR-081 | ADMIN_ROLE_EXISTS | يجب أن يكون هناك دور مسؤول واحد على الأقل | وجود سجل (1, 'admin') في جدول access |
| BR-082 | CREATOR_CANNOT_BE_NULL | المنشئ (creator) في جدول user لا يمكن أن يكون NULL | NOT NULL على creator في جدول user |

## 6. سجل النشاط والتدقيق (Audit Trail)

### 6.1 ما يتم تتبعه

| الحدث | الجدول | الحقول |
|-------|--------|--------|
| تسجيل الدخول | user_log | user, login, session_id, activity |
| تسجيل الخروج | user_log | user, logout, session_id |
| النشاط | user_log | user, activity, session_id |

### 6.2 ما لا يتم تتبعه

| الحدث | السبب |
|-------|-------|
| إنشاء سجل | لا يوجد جدول للتدقيق على تغييرات البيانات |
| تعديل سجل | لا يوجد جدول للتدقيق على تغييرات البيانات |
| حذف سجل | لا يوجد جدول للتدقيق على تغييرات البيانات |
| دخول إلى صفحة | لا يوجد تتبع لصفحات واجهة المستخدم |
| تصدير بيانات | لا يوجد تتبع لعمليات التصدير |

## 7. مقارنة مع المتطلبات الحديثة

| المتطلب | النظام القديم | الملاحظة |
|----------|--------------|---------|
| إدارة المستخدمين | ✅ موجود | جدول user مع اسم المستخدم، كلمة المرور، الاسم، البريد الإلكتروني |
| إدارة الأدوار | ⚠️ محدود | جدول access يربط المستخدمين بالأدوار كنصوص حرة، لا يوجد جدول أدوار منفصل |
| إدارة الصلاحيات細粒ة | ❌ مفقود | لا يوجد نظام صلاحيات مفصل لكل وظيفة أو عملية |
| تتبع النشاط | ✅ موجود | جدول user_log يسجل تسجيل الدخول والخروج والنشاط |
| مصادقة متعددة العوامل | ❌ مفقود | لا يوجد دعم للمصادقة الثنائية |
| تشفير كلمات المرور | ⚠️ ضعيف | كلمات المرور مخزنة بـ MD5 hash (بدون salt) |
| انتهاء صلاحية الجلسة | ⚠️ محدود | جدول user_log يسجل logout ولكن لا يوجد انتهاء تلقائي للجلسة |
| صلاحيات حسب السجل | ❌ مفقود | لا يوجد نظام صلاحيات على مستوى السجل |
| عزل بيانات الجهات | ❌ مفقود | لا يوجد عزل بيانات حسب المؤسسة أو الوحدة |

## 8. الفجوات والثغرات الأمنية

| الفجوة | معرف | الخطورة | الوصف | تأثير |
|--------|-------|---------|-------|-------|
| كلمات مرور MD5 دون Salt | GAP-AC-001 | High | كلمات المرور مخزنة بـ MD5 hash دون salt، مما يسهل كسرها عبر جداول القوس القزحي (Rainbow Tables) | خطر اختراق حسابات المستخدمين |
| عدم وجود جدول أدوار منفصل | GAP-AC-002 | Medium | الأدوار معرفة كنصوص حرة في جدول access، لا يمكن إدارة الأدوار بشكل مركزي أو إضافة وصف لها | صعوبة إدارة الأدوار والصلاحيات |
| عدم وجود صلاحيات دقيقة | GAP-AC-003 | High | لا يوجد نظام صلاحيات مفصل لكل وظيفة أو عملية، 모든 الصلاحية تعتمد على اسم الدور فقط | صعوبة تخصيص الصلاحيات لكل مستخدم |
| عدم وجود تتبع للتعديلات على البيانات | GAP-AC-004 | Medium | لا يوجد جدول للتدقيق على إنشاء أو تعديل أو حذف السجلات | صعوبة تتبع التغييرات على البيانات الحساسة |
| عدم وجود انتهاء تلقائي للجلسة | GAP-AC-005 | Low | لا يوجد انتهاء تلقائي للجلسة بعد فترة من عدم النشاط | خطر الوصول غير المصرح به إذا ترك المستخدم الجهاز مفتوحاً |
| عدم وجود صلاحيات حسب السجل | GAP-AC-006 | Medium | لا يوجد نظام صلاحيات على مستوى السجل (يمكن للمستخدم الوصول لجميع السجلات) | خطر الوصول غير المصرح به لبيانات حساسة |
| عدم عزل بيانات الجهات | GAP-AC-007 | Medium | لا يوجد عزل بيانات حسب المؤسسة أو الوحدة | خطر الوصول إلى بيانات مؤسسات أخرى |
