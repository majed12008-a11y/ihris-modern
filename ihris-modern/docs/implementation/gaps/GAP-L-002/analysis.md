# GAP-L-002 — تحليل: تصدير بيانات التقارير (CSV / PDF عربي / Excel)

> **الحالة قبل العمل:** جزئية 55% (P2) — CSV يعمل، PDF إنجليزي فقط، Excel مفقود.
> **المرجع:** `docs/legacy-modern-comparison/12-GAP-ANALYSIS.md` (السطر 38) + `ADR-004 §4.5`.
> **التاريخ:** 15 نوفمبر 2026 · **الفرع:** `feature/gap-l-002-export`

---

## 1. الوضع قبل التغيير (وقائع من الكود)

| البند | الحالة الفعلية |
|-------|----------------|
| نقطة النهاية | `POST /api/reports/:id/export?format=csv\|pdf` فقط (`routes/report.ts`) |
| CSV | ✅ UTF-8 + BOM + CRLF + quoting (`toCsv`) — يعمل مع Excel العربي |
| PDF | ⚠️ `pdfkit` بخط Helvetica، `align: "left"`، عنوان `Report #id`، **بلا تشكيل عربي** |
| Excel | ❌ غير موجود؛ لا حزمة xlsx في `backend/package.json` |
| الواجهة | `ReportExecute.tsx` كانت تُنشئ CSV **على العميل** فقط (بلا BOM ولا escaping كامل) ولا تستدعي نقطة التصدير إطلاقاً |
| اسم الملف | `report-<id>.<ext>` إنجليزي ثابت؛ لا يحمل اسم التقرير |

**السبب الجذري لضعف PDF:** `pdfkit` يرسم المحارف كما هي دون خطوة تشكيل (Arabic shaping) ولا
يطبّق خوارزمية Unicode BiDi؛ فالعربية تظهر مقطّعة ومعكوسة. هذا مُوثَّق صراحةً في `ADR-004 §4.5`
مع الحل المقترح: خط عربي + `arabic-persian-reshaper` + `bidi`.

## 2. المتطلبات (مشتقة من الفجوة)

1. PDF يقرأ العربية صحيحاً: حروف موصولة، ترتيب RTL، أرقام لاتينية داخل النص العربي سليمة.
2. مستند عربي الاتجاه: العنوان والبيانات الوصفية على اليمين، والعمود الأول في أقصى اليمين.
3. تصدير Excel (`.xlsx`) حقيقي — لا CSV مُعاد تسميته.
4. ورقة Excel باتجاه RTL، رأس مثبّت، تصفية تلقائية، أرقام تبقى أرقاماً.
5. تسميات أعمدة عربية للأعمدة المعروفة (مع الاحتفاظ بالاسم الأصلي للمجهول).
6. توحيد الواجهة على تصدير الخادم للصيغ الثلاث (CSV/Excel/PDF) بدل CSV العميل.
7. أسماء ملفات تحمل اسم التقرير بأمان (بلا حقن ترويسات).
8. عدم كسر العقد الحالي: `format=csv` و`format=pdf` يبقيان صالحين.

## 3. القرارات التصميمية

| # | القرار | البديل المرفوض | السبب |
|---|--------|----------------|-------|
| 1 | خط **Amiri Regular** (OFL 1.1) مضمَّن في `backend/assets/fonts` | الاعتماد على خط النظام | قابلية النقل + ترخيص يسمح بالتوزيع + تغطية عربية كاملة |
| 2 | تشكيل عبر `arabic-persian-reshaper` ثم `bidi-js` | تحويل HTML→PDF بمتصفح | لا متصفح في بيئة الاختبار؛ الحل النقي أخف وأسرع وأسهل اختباراً |
| 3 | رسم النص **بصرياً** (visual order) بمحاذاة يمين | إرسال النص المنطقي لـpdfkit | pdfkit لا يطبّق BiDi |
| 4 | عكس ترتيب الأعمدة في PDF | إبقاء الأعمدة LTR | مطابقة اتجاه القراءة العربية |
| 5 | `exceljs` لتوليد xlsx | كتابة XML يدوياً / CSV بامتداد xlsx | مكتبة ناضجة، RTL أصلي، قراءة/كتابة في الاختبار |
| 6 | `format=xlsx` + قبول `format=excel` كاسم بديل | `xlsx` فقط | تفادي لبس المستخدم بين الاسم الشائع والامتداد |
| 7 | تسميات عربية في **PDF/Excel فقط** | تغيير ترويسات CSV | كسر اختبار/عقد CSV الحالي بلا داعٍ |
| 8 | `Content-Disposition` مزدوج: ASCII + `filename*=UTF-8''` | اسم عربي خام | منع حقن الترويسات + دعم الأسماء العربية |
| 9 | التصدير على الخادم للصيغ الثلاث | إبقاء CSV على العميل | مصدر واحد للحقيقة + BOM/escaping موحّد |

## 5. المخاطر والمعالجة

| المخاطرة | المعالجة |
|----------|----------|
| خطأ في مسار الخط عند التشغيل من `dist/` | `resolveArabicFontPath()` يجرّب 4 مسارات ويُخفق برسالة واضحة |
| أسماء أعمدة مجهولة | `columnLabel` يعيد الاسم كما هو (لا فقدان معلومة) |
| نص مختلط عربي/لاتيني | اختبار يضمن عدم فقدان أي محرف بعد BiDi |
| ملفات كبيرة | التصدير يحترم `maxRows` المطبَّق أصلاً في `ReportService.execute` |
| حقن ترويسة عبر اسم التقرير | اختبار باسم يحتوي `"` و`\r\n` |
| ترخيص الخط | `OFL.txt` مرفق بجانب الخط |

## 6. معايير القبول

1. `format=csv` بلا تغيير سلوكي (BOM/CRLF/quoting).
2. `format=pdf` يعيد PDF صالحاً يضمّن خط Amiri، ويُشكّل العربية.
3. `format=xlsx` (و`excel`) يعيد ملف ZIP صالحاً بورقة RTL ورأس عربي.
4. صيغة غير مدعومة → 400 برسالة تذكر `csv, pdf or xlsx`.
5. التصدير بلا توكن → 401.
6. الواجهة تنزّل الصيغ الثلاث من الخادم وتستخدم اسم الملف من الترويسة.
7. Regression كامل نظيف (250 backend + 7 frontend).
