# تحليل الفجوة الحرجة - GAP-002

## 1. معلومات الفجوة

| البند | القيمة |
|-------|--------|
| معرف الفجوة | GAP-002 |
| العنوان | تعديل مستخدم |
| المجال | إدارة المستخدمين |
| الخطورة | عالية |
| درجة الثقة | مؤكدة |

## 2. وصف الفجوة

لا يوجد نموذج لتعديل المستخدمين عبر واجهة المستخدم. جدول `user` يسمح بتعديل بيانات المستخدمين، وAPI للتعديل موجود (`PUT /api/users/:id`) ولكن واجهة المستخدم مفقودة.

## 3. الأدلة المرجعية

| معرف الدليل | العنصر | المصدر | النوع | مستوى الثقة |
|-------------|--------|---------|-------|-------------|
| EVID-101 | نموذج `User` | Prisma Schema | `backend/prisma/schema.prisma` | FACT | مؤكدة |
| EVID-154 | مسار API `/api/persons` | كود الخلفية | `backend/src/routes/person.ts` | FACT | مؤكدة |

## 4. الفرق بين النظام القديم والحديث

| البند | النظام القديم | النظام الحديث |
|-------|-------------|-------------|
| تعديل المستخدم | واجهة مستخدم لتعديل بيانات المستخدمين عبر جدول `user` | لا يوجد واجهة مستخدم لتعديل المستخدمين، API موجود فقط |
| تخزين كلمة المرور | MD5 hash | bcrypt hash |
| حقوق المستخدم | 명 définie في جدول `access` | نظام RBAC مع أدوار متعددة (admin, hr_manager, hr_staff, training_manager, exec_manager) |

## 5. التأثير على البيانات والوظائف

| البند | التأثير |
|-------|---------|
| التأثير على المستخدم | المستخدم لا يمكنه تحديث بيانات الحساب |
| التأثير على البيانات | لا تأثير مباشر على البيانات |
| تأثير على العمليات | المسؤولون لا يمكنهم تحديث بيانات حسابات المستخدمين، مما يحد من قدرتهم على إدارة الحسابات |

## 6. الحل المقترح

| البند | القيمة |
|-------|--------|
| الحل | تطوير واجهة مستخدم لتعديل وحذف المستخدمين عبر واجهة المستخدم، ليس فقط عبر API |
| الجهد المقدر | 1-2 أسبوع |
| الموارد المطلوبة | مطور واجهة أمامية، مطور خلفي |
| المعايير المقبولة | القدرة على تعديل بيانات المستخدم، حذف مستخدم، عرض قائمة المستخدمين مع خيارات التعديل والحذف |
