# تحليل الفجوة الحرجة - GAP-003

## 1. معلومات الفجوة

| البند | القيمة |
|-------|--------|
| معرف الفجوة | GAP-003 |
| العنوان | حذف مستخدم |
| المجال | إدارة المستخدمين |
| الخطورة | عالية |
| درجة الثقة | مؤكدة |

## 2. وصف الفجوة

لا يوجد نموذج لحذف المستخدمين عبر واجهة المستخدم. جدول `user` يسمح بحذف المستخدمين، API للحذف غير موجود في `/api/users/:id`، مما يمنع المسؤولين من إزالة المستخدمين غير النشطين من النظام.

## 3. الأدلة المرجعية

| معرف الدليل | العنصر | المصدر | النوع | مستوى الثقة |
|-------------|--------|---------|-------|-------------|
| EVID-101 | نموذج `User` | Prisma Schema | `backend/prisma/schema.prisma` | FACT | مؤكدة |
| EVID-154 | مسار API `/api/persons` | كود الخلفية | `backend/src/routes/person.ts` | FACT | مؤكدة |

## 4. الفرق بين النظام القديم والحديث

| البند | النظام القديم | النظام الحديث |
|-------|-------------|-------------|
| حذف المستخدم | واجهة مستخدم لحذف المستخدمين عبر جدول `user` | لا يوجد واجهة مستخدم لحذف المستخدمين، API للحذف غير موجودة |
| إدارة الحسابات | نظام شامل لإدارة الحسابات بما في ذلك الحذف | نظام جزئي لإدارة الحسابات (إضافة فقط عبر واجهة المستخدم، تعديل عبر API) |

## 5. التأثير على البيانات والوظائف

| البند | التأثير |
|-------|---------|
| التأثير على المستخدم | لا يمكن إزالة المستخدمين غير النشطين |
| التأثير على البيانات | لا تأثير مباشر على البيانات |
| تأثير على العمليات | المسؤولون لا يمكنون إزالة المستخدمين غير النشطين، مما قد يؤدي إلى تراكم حسابات غير مستخدمة في النظام |

## 6. الحل المقترح

| البند | القيمة |
|-------|--------|
| الحل | تطوير واجهة مستخدم لحذف المستخدمين عبر واجهة المستخدم، وإنشاء API للحذف (`DELETE /api/users/:id`) |
| الجهد المقدر | 1-2 أسبوع |
| الموارد المطلوبة | مطور واجهة أمامية، مطور خلفي |
| المعايير المقبولة | القدرة على حذف مستخدم عبر واجهة المستخدم، وجود API `DELETE /api/users/:id`، اختفاء المستخدم من القائمة بعد الحذف |
