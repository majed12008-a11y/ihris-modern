## 2. وصف الفجوة

لا يوجد نموذج لحذف المستخدمين عبر واجهة المستخدم. جدول `user` يسمح بحذف المستخدمين، API للحذف غير موجود في `/api/users/:id`، مما يمنع المسؤولين من إزالة المستخدمين غير النشطين من النظام.

## 9. الحالة الفعلية (Sprint 2 — المرحلة 1)

> فُحص الكود الفعلي وقاعدة `ihris_test_gap001` بتاريخ 05 نوفمبر 2026.

### 9.1 ما الموجود فعلاً في النظام الحديث؟

| العنصر | الموجود | التفاصيل |
|--------|---------|----------|
| API الحذف | ❌ **مفقود بالكامل** | لا `DELETE /api/users/:id`، ولا أي مسار حذف في `routes/user.ts`. |
| Soft Delete | ❌ **غير موجود** | لا أعمدة `deletedAt` / `deletedBy` / `deletionReason` على `users`. |
| الاستعادة | ❌ **غير موجودة** | لا مسار restore ولا `restoredAt`. |
| قائمة المحذوفين | ❌ **غير موجودة** | `GET /api/users` يعيد كل الصفوف بلا تصفية (وحتى لو وجدت أعمدة، لا تصفية). |
| Audit | ❌ **غير موجود** | لا جدول `user_audit_log`. |
| Optimistic Lock | ❌ **غير موجود** | لا عمود `version`. |
| واجهة الحذف/الاستعادة | ❌ **غير موجودة** | لا زر حذف، ولا modal سبب، ولا صفحة "المستخدمون المحذوفون". |
| الصلاحيات | ⚠️ جزئية | `requireRole("admin")` متاح، لكن لا يوجد أي مسار حذف/استعادة أصلاً. |

### 9.2 القيود الفعلية — جداول FK إلى `users`

تم استخراجها من `information_schema` في `ihris_test_gap001`:

| الجدول | العمود | `delete_rule` | التصنيف |
|--------|--------|---------------|---------|
| `user_access` | `userId` | `CASCADE` | ملكية داخلية (دور) |
| `report_preferences` | `userId` | `CASCADE` | تفضيلات شخصية |
| `report_definitions` | `createdBy` | `NO ACTION` | **سجل عمل** |
| `report_executions` | `executedBy` | `NO ACTION` | **سجل عمل** |

**قرار كشف السجلات المرتبطة:** خيار **A + B**:
- **A (فحص مسبق):** `hasRelatedRecords(userId)` يعدّ الصفوف في `report_definitions` و`report_executions` فقط (جداول سجلات العمل). إن وُجدت → `422` برسالة عربية واضحة تقترح التعطيل.
- **B (شبكة أمان):** قيود `NO ACTION` الحالية على الجدولين ترفض أي حذف فيزيائي مباشر. لن نغيّرها إلى `CASCADE`، ولن نضيف `ON DELETE RESTRICT` صراحةً لأن `NO ACTION` في PostgreSQL ترفض الحذف عند وجود صفوف مرجعية (الفرق الوحيد هو التقييد المؤجل، وهو غير مستخدم هنا).
- `user_access` و`report_preferences` لا تمنعان الحذف (بيانات ملكية داخلية، وتُنظَّف عند purge النهائي في P3).
