# تحليل GAP-005 — تعديل منشأة

> التاريخ: 06 نوفمبر 2026 — قبل التنفيذ.

## 1. الحالة الفعلية قبل التنفيذ

| البند | الحالة |
|-------|--------|
| `PUT /api/facilities/:id` | موجود لكنه يمرّر `req.body` مباشرة |
| Optimistic Lock | ❌ لا `version` أصلاً في `facilities` |
| التدقيق | ❌ لا سجل |
| التحقق | ❌ لا Zod |
| صفحة التعديل | `FacilityForm.tsx` غير مربوط، ولا يعبّئ البيانات بشكل صحيح |

## 2. المطلوب وفق ADR-006

1. إضافة `facilities.version` (ترحيل 005).
2. `updateMany({ where: { id, version } })` → 409 عند `count === 0`.
3. `version++` مرة واحدة عند النجاح.
4. Audit `update` مع old/new.
5. Zod strict يتطلب `version` ويرفض جسماً بلا حقول.
6. cascade يعمل في وضع التعديل مع prefill.

## 3. سؤال BR-097 عند التعديل

البيانات القديمة قد تكون ناقصة الحقول الأربعة. فرض BR-097 على كل تعديل يمنع
تعديل الاسم فقط. القرار: **يُتحقق BR-097 فقط إذا مُسّ أي حقل موقع**، وإلا يُسمح
بتعديل الحقول الأخرى مع الحفاظ على القيم القديمة.

## 4. القرار

تنفيذ version lock + audit + Zod + prefill، مع استثناء BR-097 المشروط.

## 5. خارج النطاق

- تعديل جماعي.
- استعادة بعد الحذف (لا Soft Delete).
